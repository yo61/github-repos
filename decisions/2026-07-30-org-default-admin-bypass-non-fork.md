## Decision: Add the repository Admin role (`RepositoryRole` id 5) as an org-wide default bypass actor on the `default_branch` ruleset, but only for **non-fork** repos. Implement the fork exclusion with a `github_repositories` `fork:false` query in `modules/org`, via a new `default_branch_ruleset_non_fork_bypass_actors` variable, so no per-repo `is_fork` flag is maintained.

## Context: Rolling the review-gated auto-merge pattern out to several active repos means each needs a repository-admin bypass so the maintainer isn't blocked on their own PRs by the `required_approving_review_count: 1` rule. Restating that bypass in every repo's YAML duplicates it and risks going stale. An org-wide default was the obvious DRY fix, but the org module fans out over all 191 managed repos and 165 of them (86%) are forks the maintainer does not care about — a blanket default would stamp the bypass onto every fork's ruleset. Forks are being considered for a separate pruning/unprotecting effort.

## Alternatives considered:
- Per-repo bypass coupled to the auto-merge pattern (no org default) — rejected: chosen against; the maintainer wants a single org-level default, and repeating the admin bypass across repos invites drift.
- Blanket org default across all 191 repos (forks included) — rejected: adds a bypass to 165 forks that are out of scope and produces a large, noisy plan.
- Hand-maintained `is_fork: true` flag per data file — rejected: 191 files to annotate and keep in sync; GitHub already knows fork status.
- Time-based "active" filter (only repos pushed in the last N months) — rejected: `pushed_at` is non-deterministic, so a repo going quiet would silently lose its bypass; fork status is stable.

## Reasoning: GitHub's `search` API answers `org:yo61 fork:false` directly (verified: 26 results, matching the managed non-fork count exactly), so fork status is read live and needs no local bookkeeping — the same pattern the module already uses for drift detection. The base `default_branch_ruleset_bypass_actors` (semantic-release-pusher) still applies to every repo, leaving forks untouched; the new `default_branch_ruleset_non_fork_bypass_actors` (admin role) is concatenated only when the repo is in the non-fork set. Applying admin-bypass to all 26 non-forks (not just the 14 active ones) is harmless: bypass has no effect on a ruleset without a review requirement, and the 12 inactive non-forks simply carry a dormant bypass until they are enabled or pruned. A per-repo `default_branch_ruleset_bypass_actors` override still replaces the whole list, so opt-outs like `homebrew-tap` (`[]`) are preserved.

## Trade-offs accepted: The plan now depends on a second live `github_repositories` query at plan time (eventual consistency and rate limits apply, as they already do for drift detection). The 12 inactive non-fork repos gain a dormant admin bypass. The 165 forks remain managed and protected for now; pruning/unprotecting them is a separate, later effort, after which the non-fork set shrinks automatically.
