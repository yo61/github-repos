## Decision: Drive `plan`/`apply`/state inspection with the native `terraform` CLI against Stategraph's HTTP backend, and retire the `stategraph tf` and `stategraph sql` wrappers from the `Taskfile`. Commit the backend as a **partial** configuration in `backend.tf` (`backend "http" { username = "terraform" }`), supplying both `TF_HTTP_ADDRESS` and `TF_HTTP_PASSWORD` from the environment, and delete the gitignored `backend_override.tf`.

## Context: `stategraph tf plan` has been failing on this state with a 404 on the transaction `/logs/append` write path (tx `06747cad`, tracked at stategraph/releases#3, first seen 2026-08-02). Applies have in practice been going through the native `terraform` CLI against the same state via a local `backend_override.tf` — including the `unifi-mcp` security-check gate, which `decisions/2026-08-04-gate-apply-ordering-and-classic-protection-drift.md` recorded as "apply is blocked". Verified at the time of this decision: ruleset `20294163` on `unifi-mcp` carries all six declared contexts, and both classic branch protection rules (`unifi-mcp`, `claude-skills`) return `404 Branch not protected`, so that apply and both drift deletions have in fact landed.

The `Taskfile` therefore documented a path nobody was using and that did not work. `CLAUDE.md` repeated the same commands, and `prefer-task-wrappers` guidance pointed at wrappers whose write path was broken.

`backend_override.tf` matched `*_override.tf` in `.gitignore`, so it existed only on one machine. That is the dangerous part of moving to native terraform: with the file absent, `terraform init` does not fail — it configures a **local** backend, and `plan` then proposes creating all 130 instances from scratch. The failure renders as an ordinary plan. Under `stategraph tf` this could not happen, because the state binding came from the CLI rather than from a file in the working directory.

## Alternatives considered:
- **Keep the `stategraph tf` wrappers and wait for the upstream fix.** Rejected: the write path has been broken since 2026-08-02 with no fix, it already stalled the Phase-0 apply, and work has routed around it regardless. The `Taskfile` should describe what is actually used.
- **Keep both paths — `task plan` on stategraph, `task plan:tf` on terraform.** Rejected under "replace, don't deprecate". Two ways to reach one state invites applying through the broken one, and the file-vs-CLI state binding differs between them, which is exactly the ambiguity that produced the footgun.
- **Commit the full backend including `address`.** Rejected by Robin: this repository is public, so the committed address would publish the state UUID permanently in git history. It is an identifier behind authentication rather than a credential, and backend addresses are conventionally committed, but partial configuration costs only one extra environment variable.
- **Leave `backend_override.tf` gitignored and have the `Taskfile` check for it.** Rejected: a preflight check can only report the missing file after the fact, and a fresh clone still cannot run anything. Declaring `backend "http" {}` in a committed file makes the local-state fallback structurally impossible rather than merely detected.
- **Retain `stategraph sql` for `state:list`/`state:show`.** Rejected: `terraform state list` returns the same addresses without a second tool or a `states resolve` lookup. The `status` column the SQL query returned has no terraform equivalent and was not load-bearing.

## Reasoning: Stategraph remains the state store; only the client changes. The HTTP backend is a supported Stategraph interface and is the one that currently works for writes, so this removes a dependency on a broken code path without moving state or changing any resource. Committing `backend.tf` converts the worst failure mode from silent (local state, plan-to-recreate-everything) into impossible, because the backend type is now declared in tracked code. The remaining environment dependencies fail loudly: `task` refuses to run when either variable is unset, with a message naming the variable and its expected value, rather than letting terraform prompt for an address or return a bare 401.

Verified after the change: `terraform init -reconfigure` succeeded, `task plan` reported `No changes. Your infrastructure matches the configuration.` against 130 instances, and both preflight guards fail before terraform is invoked.

## Trade-offs accepted:
- **The backend is unlocked.** Stategraph exposes no lock endpoint on this backend, so concurrent applies are unprotected. Acceptable for single-operator use; it is the same exposure the local override already had.
- **Two environment variables are required per shell**, and `TF_HTTP_ADDRESS` is now the only place the state UUID lives outside Stategraph; losing it means recovering the UUID from the Stategraph UI. They live in a direnv `.envrc` in the repository directory (corrected 2026-08-04: this decision originally said `~/.extra`). Keeping them in the working directory means a file holding a live API key sits inside a public repository, so `.envrc` is ignored by this repo's own `.gitignore` rather than by a machine-global one — otherwise the protection does not survive a fresh clone, a second machine, or CI.
- **The one-time transition needs `terraform init -reconfigure`**, because the backend configuration moved from a file argument to an environment variable. `task init` runs a plain `terraform init`; anyone re-pointing `TF_HTTP_ADDRESS` at a different state must reconfigure by hand.
- **The `stategraph`, `stategraph-change`, and `stategraph-query` skills no longer describe this repo's plan/apply path.** They remain accurate for the underlying CLI and for import/refactor work, but are no longer the route for routine changes here.
- Stategraph's broken `/logs/append` write path is worked around, not fixed, and stategraph/releases#3 stays open.

## Supersedes: the plan/apply mechanics in `CLAUDE.md` and the `Taskfile` only. No prior decision record covered the CLI choice, and no policy decision (gates, tiers, repo scope) is affected — this changes how changes are applied, not what is applied.
