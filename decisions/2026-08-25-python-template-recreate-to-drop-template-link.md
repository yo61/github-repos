## Decision: Recreate `yo61/python-template` as a fresh repo to clear its `template_repository` attribution, keeping the original as an archived `python-template-archived`. A full mirror backup was taken first, and the 38 pull-request head refs it preserves are the only surviving record of that review history.

## Context: Every `terraform plan` carried a permanent one-resource diff on `python-template` proposing to remove a `template` block (`owner = "BrianPugh"`). The repo was created from `BrianPugh/python-template` in 2024 and adopted into Terraform in PR #75 on 2026-08-24. The diff was a no-op that could never converge, and it made the plan non-empty on every run — eroding the "read the plan before applying" discipline that `quality/criteria.md` depends on. Robin's stated goal was not merely a clean plan but removing the "generated from BrianPugh/python-template" attribution GitHub shows on the repo page.

## Alternatives considered:
- **`ignore_changes = [pages, template]` in `modules/github-repo`.** Verified to work — one line, plan clean, nothing destroyed. Rejected only because it does not touch the attribution banner, which was the actual goal. It remains the right fix if a future repo is generated from a template and the banner is acceptable.
- **Declare `template:` in `data/yo61/python-template.yaml` to match state.** Would converge the plan (the field is not `ForceNew`, so no replacement risk), but records create-only input as if it were desired config, and likewise leaves the banner.
- **Clear `template_repository` through the API.** Impossible. `PATCH /repos/{owner}/{repo}` accepts 26 body parameters and none of them is `template_repository`; the field is immutable creation provenance like `fork`/`parent`. `is_template` is unrelated — it controls whether the repo can serve *as* a template.
- **Apply the removal and hope it sticks.** Tested on 2026-08-25 and empirically disproved: the diff returned on the very next plan. `resourceGithubRepositoryRead` (provider v6.13.0, line 890) unconditionally sets `template` from `repo.TemplateRepository`, `resourceGithubRepositoryUpdate` never references the field, and Update ends by calling Read.
- **Delete the original outright.** Rejected in favour of rename-then-archive, which preserves the history and leaves a rollback window.

## Reasoning: The attribution is immutable server-side, so recreation is the only mechanism that removes it. Renaming first (rather than deleting first) frees the name immediately, keeps the original reachable throughout, and makes every step before the archive reversible. Reconciliation turned out to need no state surgery at all: resources keyed on repo *name* re-bound to the new repo on refresh, while those keyed on numeric IDs (both rulesets, Pages) 404'd and planned as ordinary creates. The apply was `3 added, 3 changed, 0 destroyed`, and the resulting plan reports "No changes".

## Trade-offs accepted: The 38 pull requests and their review discussion are gone from the GitHub UI; only their head commits survive, in the mirror at `/Users/robin/code/github.com/yo61/python-template-backup.git`. The repo's numeric id changed (491578092 → 1346432509), so any external reference by id is broken. The open release-please PR (#32) was not carried over — it regenerates itself on the next release run. The `release-please--branches--main--components--python-template` branch was deliberately not pushed, being a bot artifact. The org now carries an extra archived repo, handled by `decisions/2026-08-25-exclude-archived-from-drift-detection.md`.

## Supersedes: none. Follows `decisions/2026-08-04-native-terraform-http-backend.md`, whose native-CLI access made the reconciliation inspectable before applying.
