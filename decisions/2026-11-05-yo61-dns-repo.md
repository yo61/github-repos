## Decision: Manage the DNS for every yo61 domain in one new private repo, `yo61/dns`, as Terraform against Cloudflare.

## Context: `yo61/www-yo61-com` (PR #155) will serve www.yo61.com from Cloudflare Pages, and `www.yo61.com` has no DNS record yet. The `yo61.com` zone is already on Cloudflare (`felipe`/`mira` nameservers) but no repo manages its records. This repo manages GitHub only, so the DNS needed a home somewhere else.

## Alternatives considered:
- Add it to `yo61/homelab-infrastructure`. Rejected: that repo already has the Cloudflare provider, but it is scoped to homelab resources (tunnels, AIStor buckets). Public-site DNS would turn it into a catch-all.
- One repo per site, for example `yo61/yo61-com-infrastructure`, as `horopter-dev/infrastructure` does for `horopter.dev`. Rejected: yo61 owns several domains, and DNS is one concern however many zones it covers. A repo per zone would duplicate the provider and credentials setup for each one.
- Put it in `www-yo61-com` itself. Rejected: that repo is public, so zone and account topology would be public, which is the reason `decisions/2026-09-21-infrastructure-branch-protection-declined.md` kept the horopter infrastructure private.

## Reasoning: One private repo per concern rather than per zone. It keeps record topology private, and adding a domain means adding a zone, not a repo.

## Trade-offs accepted: As a private repo on the free-plan org it gets no rulesets or secret scanning (`decisions/2026-08-10-private-repos-manual-review-gate.md`). Every yo61 zone shares one Cloudflare credential and one state, so a bad apply can affect all of them at once.

## Supersedes: none.

## Superseded: 2026-11-05 by `decisions/2026-11-05-yo61-cloudflare-in-infrastructure.md`, which puts yo61's DNS and the rest of its Cloudflare config in the existing `yo61/infrastructure` instead. `yo61/dns` was deleted before anything was pushed to it.
